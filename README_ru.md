# Infio Copilot Free

**Язык:** [English](README.md) | Русский | [简体中文](README_zh-CN.md)

AI-ассистент для Obsidian по мотивам Cursor: агентный чат, который читает и
редактирует ваше хранилище, семантический поиск на основе RAG, инлайн-
автодополнение и AI-инсайты — при полностью локальном хранении и без телеметрии.

**Infio Copilot Free** — независимое поддерживаемое сообществом продолжение
[Infio Copilot](https://github.com/infiolab/infio-copilot) (0.8.x, не
поддерживается с 2025 года и удалён из каталога плагинов Obsidian), который
сам начинался как [Smart Composer](https://github.com/glm454/smart-composer).
Все заслуги за оригинальный дизайн и код принадлежат их авторам; этот проект
устранил оставленные критические проблемы (мёртвый хост ассетов, телеметрия,
падения интерфейса) и продолжает развивать плагин.

## Возможности

- **Агентный чат с хранилищем** — ассистент читает заметки, ищет по ним
  (семантически / BM25 / regex), загружает веб-страницы, создаёт и
  редактирует файлы через проверяемые диффы и умеет использовать
  MCP-инструменты.
- **RAG-семантический поиск** — векторный индекс ваших заметок, хранящийся
  локально (PGlite — PostgreSQL, скомпилированный в WebAssembly, на OPFS).
- **AI-инсайты** — подробные и краткие саммари, ключевые идеи, анализ статей
  и другие преобразования заметок.
- **Автодополнение** — инлайн-дополнение кода/текста выбранной вами моделью.
- **Любой провайдер** — OpenAI, Anthropic, Google, OpenRouter, DeepSeek,
  Groq, xAI, Moonshot, SiliconFlow, Alibaba Qwen, OpenAI-совместимые
  эндпоинты, Ollama и другие локальные серверы, а также встроенные локальные
  эмбеддинг-модели (API-ключ для эмбеддингов не нужен).
- **Рабочие области, пользовательские режимы, быстрые команды, MCP-серверы.**
- **Локализованный интерфейс** — английский, русский и упрощённый китайский
  следуют языку интерфейса Obsidian; любой другой язык отображается на
  английском.

## Установка

### Из релиза (вручную)

1. Скачайте `obsidian-infio-copilot-free-<version>.zip` из
   [Releases](../../releases/latest) и распакуйте в
   `<vault>/.obsidian/plugins/infio-copilot-free/`.
   В папке должны находиться `main.js`, `manifest.json`, `styles.css` и три
   файла рантайма PGlite: `postgres.wasm`, `postgres.data`, `vector.tar.gz`.
2. Перезапустите Obsidian и включите **Infio Copilot Free** в разделе
   Настройки → Сторонние плагины.

Если трёх файлов PGlite не окажется, плагин всё равно запустится: они будут
однократно загружены с npm CDN-зеркал (jsDelivr → npmmirror → unpkg).

### BRAT

Добавьте этот репозиторий в [BRAT](https://github.com/TfTHacker/obsidian42-brat),
чтобы получать сборки из релизов автоматически.

### Каталог плагинов

В каталоге пока не значится — заявка в `obsidianmd/obsidian-releases`
запланирована; до её одобрения используйте два способа выше.

## Первые шаги

1. Откройте чат с ленты (иконка волшебной палочки) или из палитры команд
   («Open Infio Copilot Free»).
2. В разделе Настройки → Infio Copilot Free выберите провайдера и вставьте
   API-ключ — либо укажите для Ollama адрес `http://localhost:11434`: тогда
   списки моделей подтягиваются прямо с вашего сервера Ollama, а кнопка
   **Test connection** диагностирует и доступность сервера, и проблемы
   CORS/origin (см. раздел «Ollama (локальные модели)» ниже).
3. Настройте четыре слота моделей (чат / apply / инсайты / эмбеддинги) —
   каждый задаётся отдельно. Для эмбеддингов доступны встроенные локальные
   модели.
4. По желанию: постройте семантический индекс в панели «Semantic Index» и
   включите автодополнение внизу вкладки настроек.

## Ollama (локальные модели)

Infio Copilot Free работает с [Ollama](https://ollama.com) «из коробки»:

1. Установите Ollama и скачайте модель, например `ollama pull qwen2.5:3b`.
2. Убедитесь, что сервер запущен (`ollama serve`; десктопные приложения
   запускают его автоматически). Адрес по умолчанию:
   `http://localhost:11434`.
3. В разделе Настройки → Infio Copilot Free → **Ollama** укажите базовый URL.
   Списки моделей чата/инсайтов/автодополнения подтягиваются с сервера
   (`/api/tags`) автоматически, а в списке эмбеддинг-моделей показываются
   модели сервера с поддержкой эмбеддингов (Ollama сообщает capabilities
   моделей; на старых версиях показывается полный список). Любое другое имя
   модели можно ввести вручную.
4. Нажмите **Test connection** под полем базового URL и следуйте вердикту
   (см. ниже).

Запросы чата и эмбеддингов используют OpenAI-совместимый API Ollama на `/v1`
(Ollama ≥ 0.1.14). Список моделей загружается через нативный HTTP-слой
Obsidian, на который браузерный CORS не распространяется.

### Как читать результаты Test connection

| Результат | Значение | Что делать |
|---|---|---|
| **OK** (показывает версию сервера) | Сервер доступен и принимает запросы Obsidian | Ничего — всё готово |
| **Cannot reach Ollama** | Нативный запрос не прошёл | Ollama запущена (`ollama serve`)? Базовый URL/порт верны? Не мешают ли файрвол/прокси? |
| **Reachable, but rejects browser requests** | Сервер отвечает на нативные запросы, но блокирует `fetch` рендерера — это политика `OLLAMA_ORIGINS` | См. рецепт ниже |
| **Set the base URL first** | Адрес не задан | Заполните базовый URL Ollama |

### Зачем нужен OLLAMA_ORIGINS (и как его задать)

Запросы чата/эмбеддингов выполняются через `fetch` рендерера, поэтому Ollama
видит их как кросс-доменные вызовы с origin `app://obsidian.md`. По умолчанию
Ollama разрешает только localhost-источники, а остальным отвечает `403` —
браузеры скрывают такой ответ как непрозрачную ошибку «Failed to fetch»
(ту же, что при выключенном сервере; кнопка Test connection их различает).

Разрешите origin Obsidian (или все источники через `*`) и **перезапустите
Ollama**:

- **Windows** (PowerShell, затем перезапустите приложение Ollama):
  `setx OLLAMA_ORIGINS "app://obsidian.md"` — или задайте через
  *Система → Переменные среды*.
- **macOS** (терминал, затем закройте и снова откройте приложение Ollama):
  `launchctl setenv OLLAMA_ORIGINS "app://obsidian.md"`
- **Linux** (сервис systemd): `sudo systemctl edit ollama` и добавьте
  ```ini
  [Service]
  Environment="OLLAMA_ORIGINS=app://obsidian.md"
  ```
  затем `sudo systemctl daemon-reload && sudo systemctl restart ollama`.

Удобная диагностика: если список моделей **подтягивается**, а чат всё равно
падает с сетевой ошибкой, — это почти наверняка политика origins (список
использует нативный HTTP, чат — `fetch`).

## Приватность

- Никакой телеметрии, аналитики и кода самообновления (причины делистинга
  апстрим-плагина устранены).
- Вашу машину покидают только обращения к настроенному вами LLM-провайдеру.
- Чаты, векторный индекс и настройки хранятся локально в профиле хранилища.

## Заметки для обновляющихся с Infio Copilot

- ID плагина изменён на `infio-copilot-free`; он устанавливается рядом со
  старым. Настройки не мигрируют автоматически — скопируйте `data.json` между
  папками плагинов, если хотите их сохранить, затем удалите старый плагин.
- База чата/векторов сохраняет прежнее имя хранилища (`infio-db`) для
  преемственности данных. **Не** запускайте оба плагина одновременно: они
  будут делить эту базу.
- CSS-сниппеты, нацеленные на классы `.infio-*`, должны перейти на новый
  префикс `icf-*`.

## Сборка из исходников

Требования: Node 20, pnpm 12.

```bash
pnpm install
pnpm build               # type-check + esbuild production bundle -> main.js
pnpm copy-pglite-assets  # PGlite runtime files -> pglite-assets/
pnpm test
```

Скопируйте `main.js`, `manifest.json`, `styles.css` и три файла из
`pglite-assets/*` в папку плагина вашего хранилища и перезагрузите Obsidian
(Ctrl/Cmd+R).

Процесс релизов, заметки о CI и дорожная карта — в
[MAINTAINING.md](MAINTAINING.md).
