# Дорожная карта: от «минимально рабочего» к «хорошему плагину»

Цель: Infio Copilot Free, который не вызывает вопросов ни у пользователей,
ни у ревьюеров каталога: надёжный, быстрый, полностью локализованный,
с честными платформенными ограничениями и покрытиями тестами.

Формат работы: каждая фаза = один релиз (1.1.0, 1.2.0, …) с фокусным
скоупом, патч → применение → релиз → проверка.

Все фактические утверждения ниже сверены с аудитом кода на v1.0.7
(2026-09-21); числа — реальные замеренные значения, а не оценки.

## Фаза 0 — «Гигиена» + блокеры листинга (релиз 1.1.0)

### 0.0 Быстрые победы и решение до подачи (независимые мини-PR, можно сразу)

1. **Решение по `isDesktopOnly`.** Сейчас в манифесте `false`, но мобильный
   путь = одна вкладка настроек (`loadMobile` в `main.mobile.ts`) с китайским
   текстом и предложением ввести API-ключ мёртвого сервиса. До фазы 1 честно
   поставить `isDesktopOnly: true` (вернуть `false` после мобильного паритета)
   — ревьюеры каталога проверяют заявленные платформы.
2. **Удалить мёртвую зависимость `@huggingface/transformers`** из
   `package.json`: в `src/` не импортируется нигде (в отличие от
   `@xenova/transformers`, который реально используется в `embed.worker.ts`).
3. **Удалить мёртвый `checkGeneral()`** и его дубль в `main.mobile.ts`
   (отправка `device_id`/`device_name` на `api.infio.app`; вызывающих нет,
   но код лежит в бандле — privacy red flag для каталога).
4. **Подключить уже готовый `getOllamaModels()`** (`src/utils/ollama.ts`,
   `requestUrl` + `/api/tags`) к UI настроек — утилита написана, но не
   используется ни в одном компоненте.
5. **Синхронизация документации сборки:** `MAINTAINING.md` говорит pnpm 9,
   CI ставит pnpm 12 — привести к одному значению.

### 0.1 БЛОККЕР ЛИСТИНГА — удалить мёртвый облачный провайдер Infio

Сервис `api.infio.app` мёртв (признано в `MAINTAINING.md`), но интеграция
жива и глубже, чем «мёртвый код»:

- `fetchUserPlan()` из `use-infio.ts` **вызывается** в
  `ModelProviderSettings.tsx` → плагин до сих пор ходит на `api.infio.app`;
- `ApiProvider.Infio` — дефолтный fallback (`.catch(ApiProvider.Infio)`)
  для шести полей в `types/settings.ts` (defaultProvider, activeProviderTab,
  chat/insight/apply/embeddingModelProvider) → нужна миграция настроек на
  провайдер по умолчанию + дефолты в zod-схемах;
- Pro-модалки, built-in MCP через Infio, `INFIO_BASE_URL`/`INFIO_PLATFORM_URL`
  в `constants.ts`.

Критерий готовности: grep по исходникам и по собранному `main.js` не находит
`api.infio.app`; миграция старых настроек покрыта тестом.

### 0.2 Диета зависимостей

- `langchain` используется в ровно одном месте
  (`RecursiveCharacterTextSplitter` в `database/modules/vector/vector-manager.ts`)
  → локальный сплиттер (~60 строк + тесты), зависимость убрать.
- `@xenova/transformers` (v2, deprecated) в `embed.worker.ts` → решить
  направление миграции: на `@huggingface/transformers` (v3, уже заявлен в
  devDeps-экосистеме) или остаться на v2 с фиксацией; после 0.0.2 дубля в
  `package.json` не будет — это именно миграция, а не дедупликация.

### 0.3 Ollama первого класса

Уточнение после аудита: embeddings уже идут через OpenAI-совместимый
`/v1` (`NoStainlessOpenAI` в `core/rag/embedding.ts`) — для современных
версий Ollama это рабочий путь, «чинить» там нечего. Реальные работы:

1. список моделей в настройках через готовый `getOllamaModels()` (см. 0.0.4);
2. ошибка-подсказка про `OLLAMA_ORIGINS`/CORS при сетевых сбоях Ollama
   (сейчас её нет);
3. health-check базового URL + ссылка на CORS-гайд из README.

### 0.4 Локализация всех строк UI

Замер: ~1583 строки с CJK-символами вне `src/lang/locale/` — в основном
комментарии, но есть и UI-строки (весь `MobileSettingTab`, хардкоды вроде
`'Ollama Address is missing…'`). Инфраструктура i18n готова: 24 локали,
en/ru/zh-cn синхронны (~652 ключа).

1. Все пользовательские строки → `t()`; комментарии — по желанию.
2. **Политика локалей (решено 2026-09-22):** поставляются только en/ru/zh-cn;
   остальные 21 локаль удалены, прочие языки интерфейса отображаются на en;
   синхронность ключей/плейсхолдеров трёх локалей контролирует тест в CI;
   политика зафиксирована в CONTRIBUTING.
3. Тест полноты ключей для первичных локалей (en/ru/zh-cn) в CI.

### 0.5 `confirm`/`alert` → модалки; logger

- `confirm`/`alert` — 8 мест, перевести на Obsidian-модалки.
- Logger с debug-флагом: в production-сборке esbuild уже делает
  `drop: ['console','debugger']` (172 `console.log` пользователь не видит),
  поэтому это dev-эргономика и структурированные ошибки — приоритет внутри
  фазы ниже остальных пунктов.

## Фаза 1 — «Мобильный паритет + on-device AI» (релиз 1.2.0)

### 1.0 Спайк-проверка (до фиксации скоупа, ~1 неделя)

Самый рискованный пункт всей карты — PGlite (OPFS) и transformers.js внутри
мобильного WebView. До обязательств проверить на реальных устройствах
(iOS WKWebView + Android Capacitor WebView):

- PGlite: квоты хранилища, поведение при убийстве/возобновлении приложения,
  скорость индексации типового vault;
- transformers.js: загрузка модели, WebGPU/WASM-бэкенды, потребление памяти;
- итог спайка определяет скоуп: полный паритет ИЛИ «паритет минус локальная
  БД» (на мобильном — BM25/remote-embeddings, PGlite только desktop).

### Честная картина возможностей (проверено, 2026)

- **Прямой доступ к NPU (WebNN/NNAPI/CoreML) из плагина невозможен:**
  Obsidian Mobile = Capacitor WebView без нативного кода для плагинов;
  WebNN по данным chromestatus.com в 2026 всё ещё в rollout/за флагами,
  не по умолчанию.
- **Но ускорители чипов достижимы двумя путями:**
  1. **WebGPU** (GPU/нейроядро косвенно): shipped by default в Chrome/Android
     WebView; в Safari 26.0 включён для macOS/iOS/iPadOS/visionOS
     (webkit.org, сентябрь 2025); ONNX-модели через transformers.js /
     onnxruntime-web с WebGPU-бэкендом. На iOS WKWebView доступность WebGPU
     определяем runtime-детектом (`navigator.gpu`), без предположений.
  2. **Локальный OpenAI-совместимый сервер на телефоне** (Termux + llama.cpp
     с Vulkan/Qualcomm-QNN-бэкендом, серверные Android-приложения): вот это
     настоящий путь к NPU сегодня. Плагин уже умеет любой base URL → делаем
     first-class: автообнаружение `localhost:11434/8080/11435`, подсказки
     установки, health-check, стриминг.
- **WASM CPU** — fallback для старых устройств (уже работает: PGlite,
  эмбеддинги).

### Состав фазы

1. **Паритет ядра** (в объёме, утверждённом по итогам спайка 1.0):
   chat-UI, PGlite-БД (OPFS/IDB в WebView), история, инсайсы,
   семантический поиск — тем же кодом, что desktop, где это возможно.
   После доставки вернуть `isDesktopOnly: false` в манифест (см. 0.0.1).
2. **Меню «On-device AI»: Off / Auto / On** + авто-цепочка бэкендов
   `локальный сервер → WebGPU → WASM → удалённый провайдер → off`
   с runtime-пробой (navigator.gpu, deviceMemory, hardwareConcurrency,
   storage estimate) и понятной индикацией активного бэкенда в UI.
3. **Мобильные эмбеддинги:** transformers.js с бэкендом auto (WebGPU→WASM);
   опции «индексация только по Wi-Fi / на зарядке» для батарейности.
4. **Экспериментальный on-device чат** в WebView (малые квантованные модели
   0.5–1.5B) за флагом «experimental», с предупреждением о памяти;
   по умолчанию выключен.
5. **Гейты для старых телефонов:** все тяжёлые фичи лениво грузятся только
   при включении; детект слабых устройств (deviceMemory < 4, нет WebGPU)
   предлагает Off/Auto вместо On; никаких фоновых воркеров без согласия.
6. Тесты: capability-детект (моки), fallback-цепочка, мобильные сценарии чата.

## Фаза 2 — «Надёжность»: типы на границах (релиз 1.3.0)

> **Статус (1.3.0, заход 1):** Пункт 1 — частично: добавлены Zod-границы для
> Ollama `/api/tags`, OpenRouter `/models` и Serper
> (`src/utils/provider-schemas.ts` + unit-тесты); MCP-настройки уже
> валидируются `McpSettingsSchema` на основных путях загрузки, `dataview.ts`
> не содержит `any`. Пункт 4 — частично: Node-модули `https` (web-search) и
> `crypto` (ConvertDataManager) заменены кросс-платформенными аналогами
> (`requestUrl` из Obsidian API, pure-TypeScript MD5 по RFC 1321 с
> байт-идентичными хешами); оставшийся `path` (7 файлов) опирается на
> мобильный shim Obsidian — проверка в spike фазы 1. Пункт 6 — частично:
> добавлены тесты схем границ; тесты миграций настроек уже есть; i18n-полнота
> обеспечивается с 1.2.0. Остальное в заходе 2 (→ 1.3.1): пункт 2 (включение
> `no-unsafe-*` по модулям), пункт 3 (инвентаризация
> `@ts-nocheck`/`@ts-ignore`), пункт 5 (единый слой «ошибка → notice с
> действием»).

1. **Zod-схемы на всех внешних границах** (MCP JSON-RPC, JSON провайдеров,
   Dataview, Ollama/OpenRouter). Zod уже применяется в 9 файлах (схемы
   настроек) — это расширение существующей практики.
2. **Включение no-unsafe-\* правил.** Уточнение: в коде всего 2 disable-метки,
   но в `.eslintrc.js` явно выключены `no-unsafe-assignment/member-access/call`
   (а также `no-floating-promises`, `no-misused-promises`,
   `no-unnecessary-condition`) — включение даст ~600 ошибок. Порядок: сначала
   zod на границах (п.1), затем постепенное включение правил по модулям.
3. **Инвентаризация `@ts-nocheck`/`@ts-ignore`/`@ts-expect-error`**
   (сейчас 31 файл): план сокращения; запрет blanket-`@ts-nocheck`
   в core-модулях (в `main.ts` он есть).
4. **Guard'ы `Platform.isDesktop`** вокруг Node-импортов (`path`, `fs`,
   `child_process`, `https`, `os`, `crypto`, `readline` — 9 файлов,
   guard'ов сейчас 0). Важно: esbuild пакует desktop+mobile в один
   CJS-бандл без splitting — защита чисто runtime, поэтому этот пункт
   является prerequisite фазы 1 и может начинаться раньше неё.
5. Единый слой «ошибка → notice с действием» (повторить / настройки / справка).
6. Тесты: миграции настроек 0.8.x→1.x (включая миграцию Infio→default
   из 0.1), i18n-полнота, адаптеры провайдеров.

## Фаза 4 — «Скорость и вес» (релиз 1.5.0)

Отправная точка (замер релиза 1.0.7): `main.js` = **15.9 МБ**. Основные
вкладчики: статический `import mermaid` в `MermaidBlock.tsx` (mermaid 11,
~3 МБ), inline-worker с `@xenova/transformers`/onnxruntime, lexical, пачка
LLM-SDK. PGlite-ассеты уже вынесены из бандла отдельными файлами — так и
оставить.

1. Ленивый mermaid и тяжёлые Markdown-блоки (dynamic import).
2. Отложенный подъём embed-воркера; профиль холодного старта ≤ 1.5 c
   (артeфакт CI; сейчас не измеряется вовсе).
3. Диета бандла до < 10 МБ main.js; попутно — апгрейд esbuild 0.17.3
   (2023 год) с проверкой совместимости `esbuild-plugin-inline-worker`.
4. Инкрементальная индексация без полных пересборок + кеш семантического
   поиска.

## Порядок работы

Каждая фаза: я готовлю патч(и) + тесты → вы применяете и выпускаете релиз →
проверяем на вашем vault и (для фазы 1) на реальном телефоне → правки.

- Быстрые победы 0.0 — отдельными мини-PR, не дожидаясь старта фазы 0.
- Фаза 0 — один заход (0.1 блоккерный, остальное параллельно).
- Фаза 1 — спайк 1.0 (~1 неделя) → фиксация скоупа → два захода
  (паритет, затем on-device AI).
- Фаза 2 — 2–3 захода по модулям типов; п.4 (Platform-guard'ы) можно
  начинать во время фазы 1.
- Фазы 3–5 — по одному заходу, фаза 5 параллельно с остальными.
